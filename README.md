# Operating Systems -- Coursework

Coursework for Operating Systems (Pontificia Universidad Javeriana, 2025). Covers process creation and IPC with pipes, POSIX threads (pthreads), synchronization with mutexes/condition variables/semaphores, OpenMP parallel directives, shared memory (shm_open/mmap), named pipes (FIFO), signal handling, and filesystem traversal. All programs are written in C and compiled with gcc on Linux.

## Proyecto final: Sistema de Reservas Parque Berlin

Simulates a theme-park reservation system where multiple **agents** (separate processes) read reservation requests from CSV files and send them to a **controller** process via a named FIFO pipe (`/tmp/pipe_parque`). The controller runs a dedicated POSIX thread (`hilo_reservas` in `controladorFicheros/hilo.c`) that reads from the FIFO, validates capacity (`verificar_disponibilidad` in `reservas.c`), and responds with `ACEPTADA`, `REPROGRAMADA` (finds an alternative hour via `buscar_alternativa`), or `NEGADA`. Time advances via `SIGALRM` every `seg_horas` seconds, handled by `manejador_alarma` (`manejadores.c`), triggering `procesar_avance_hora` (`procesos.c`) which calls `sacar_salientes` to release capacity. A final `reporte_final.csv` is generated by `generar_reporte` (`reporte.c`) with per-hour occupancy and aggregate stats (`Estadisticas` struct: `aceptadas`, `reprogramadas`, `negadas`). Each agent communicates back through a personal FIFO (`/tmp/pipe_<nombre>`). Shared state (`Reservas`, `Estadisticas`, `hora_actual`) is protected by a single `pthread_mutex_t`.

Integrated concepts: IPC (named FIFO pipes), signal handling (SIGALRM), POSIX threads, mutex-based critical sections, CSV file I/O.

## How to compile and run

**Labs** -- each lab has its own build method:

| Directory | Build | Run |
|---|---|---|
| `Labs/Lab_01` | `gcc davidbeltrang22Julio2025.c -o lab01` | `./lab01` |
| `Labs/Lab_02` | `make` | `./matrices_BeltranGomez <N>` |
| `Labs/Lab_03` | `gcc Challenge_XX.c -o chXX` (each file individually) | `./chXX` |
| `Labs/Lab_04` | `make` | `./progra1`, `./progra2`, `./progra3` |
| `Labs/Lab_06` | `make` | `./Challenge<1-9>` |
| `Labs/Lab_07` | `make` | `./Challenge<1-5>` |
| `Labs/Lab_08` | `make` | `./Challenge<1-2>` (then enter directory name, e.g. `Patito`) |

**Talleres**:

| Directory | Build | Run |
|---|---|---|
| `Talleres/Taller_01` | `gcc tallerProceso.c -o tallerProceso` | `./tallerProceso <N1> <archivo00> <N2> <archivo01>` |
| `Talleres/Taller_02` | `make` | `./mm<Variante> <N> <hilos>`; benchmark: `perl lanzador.pl`; stats: `python3 agregar_estadisticas.py`; plots: `python3 graficar_summary.py` |

**Proyecto**:

```bash
cd Proyecto
make
# Terminal 1: controller
./controlador
# Terminal 2+: agents
./agente -s agente1 -a prueba.csv -p /tmp/pipe_parque
```

## Testing status

No automated tests exist. Individual programs can be run manually (see compile/run instructions). `Talleres/Taller_02` includes benchmarking infrastructure (Perl launcher, Python aggregation/plotting) but that is for performance measurement, not correctness verification.
